authenticated dashboard session was configured. The operator ran a single
Postgres transaction against Dokploy's own database. The transaction:

1. required exactly one compose row matching the non-secret target identity;
2. aborted if any deployment for that compose had `status=running`;
3. changed only `compose.autoDeploy`, from `true` to `false`;
4. required exactly one changed row before commit.

The transaction returned one changed row and committed. It did not invoke a
deploy endpoint, alter application environment, stop a service, rebuild an
image, change a domain, or restart Dokploy.

## Rollback compatibility and residual risk

Re-enabling push auto-deploy is not an allowed rollback. Until CH-1.7C provides
the protected immutable-image release path, the only production selection path
is a named, explicitly approved emergency/manual operator action under
`DEPLOYMENT.md`.

operator-controlled. GitHub branch protection, required checks, immutable image
promotion, staging proof, and the stopped core worker are not solved by this
containment task; later hardening tasks own them.
