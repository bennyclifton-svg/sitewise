## Result

Pass. Ordinary pytest execution now overwrites ambient and `backend/.env`
credentials before importing application code and denies Python DNS/socket
operations. Network authority requires both an `integration` or `tender_eval`
marker and the exact process-start value `CLERK_TEST_ALLOW_NETWORK=1`.

Authority is a per-test, context-local generation lease. It is invalidated at
protocol teardown, so a stale copied context or async task cannot regain access
during a later opted-in test. Raw threads do not inherit the context. Overlapping
same-process pytest protocols fail closed. A generic network opt-in never
restores `TEST_DATABASE_URL` or `ALLOW_DESTRUCTIVE_TEST_DATABASE`; CH-0.8 owns
the later disposable-database exception and its exact private-target checks.

## Residual risk and follow-up

This is deliberately Python/pytest application containment, not an OS firewall.
It cannot govern pytest plugins loaded before the root conftest, networking done
inside C libraries, or an arbitrary child executable that replaces its inherited
environment. The forced DB/libpq and provider sentinels make those ordinary
paths unreachable by default. CH-0.8 must add a separately marked, exact private
disposable-DB capability; the later network-disabled container/CI work must
provide process-tree-level proof. Same-process parallel pytest protocols remain
unsupported and fail closed.
