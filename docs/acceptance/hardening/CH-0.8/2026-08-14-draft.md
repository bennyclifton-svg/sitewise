## Implemented working-tree scope

- `TEST_DATABASE_URL` accepts only literal loopback addresses in `127/8` or
  `::1`; public, RFC1918, ULA, DNS, wildcard, and link-local targets fail before
  connection.
- Every URI query and fragment is rejected, closing libpq `host`, `hostaddr`,
  `service`, and equivalent redirection paths.
- Database authority requires exact process-start
  `DATABASE_INTEGRATION_TESTS=1` plus the `database_integration` marker. Generic
  network opt-in cannot grant database access.
- The socket guard authorizes only the validated endpoint for the active test
  capability; the ordinary offline suite remains denied.
- Alembic may select the test URL only in the dedicated lane and verifies the
  exact in-database marker `clerk_test_environment='test'` immediately after
  connecting. The marker table is excluded from schema comparison.
- `scripts/test-database.ps1` generates a unique project and credentials, arms
  cleanup before `compose up`, propagates failures, and runs teardown for the
  same project after partial startup failure. Its fake-Docker regression test
  also proves that output does not disclose the URL.
- A manual-only 15-minute CI job calls the shared runner. Ordinary CI remains
  database-disabled.
- A default migration smoke node is checked in and collectable.

The currently implemented scope contains ten files. Its canonical manifest
sorts each path and records its `HEAD` Git blob ID (or `absent`) and current
SHA-256, joins those records with LF, and hashes the result with SHA-256.
